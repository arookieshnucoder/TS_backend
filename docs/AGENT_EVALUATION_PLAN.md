# Agent 评测与后端边界清理计划

日期：2026-10-12。需求级别提交：先架构清理，再评测流程。禁止批量删除，保留测试产物。

## 调研结论

| 参考 | 本项目采用的原则 |
| --- | --- |
| [AgentBench](https://arxiv.org/abs/2308.03688) | 多维任务、交互环境、错误分类，避免只看一句回答 |
| [τ-bench](https://arxiv.org/abs/2406.12045) | 检查终态与策略，重复运行测一致性 pass^k |
| [HumanEval](https://arxiv.org/abs/2107.03374) | pass@k 使用有限样本组合估计，不能把重试后的成功率当首次成功率 |
| [FActScore](https://arxiv.org/abs/2305.14251) / [Ragas](https://arxiv.org/abs/2309.15217) | 区分事实覆盖、引用和支持性；字符串命中不能证明所有自然语言事实正确 |
| [Anthropic agent evals](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents) | 隔离试验，确定性评分优先，检查失败记录，验证评分器，保留能力与回归评测的区别 |

评测任务由本项目自行设计，不复制公开 benchmark 的题库。脚本模型用于控制 harness 的故障/行为，不能证明实际 LLM 的泛化或安全能力。真实模型模式独立运行，缺少凭据时明确失败。

## 架构清理

- 删除 generating 状态迁移和缺失会话状态的隐式补全，拒绝旧格式，不改写既有数据。
- AskAgent 负责决策循环、观察和终止；harness 负责模型协议、可用工具、批次 ID、预算、取消、超时、重试和事件。
- 自定义 workflow 也受相同运行限制；整个工具批次在执行前进行协议校验。
- 工具声明依赖独立契约；业务检索依赖 TextCompressor 接口；模型适配器只接收 LLM 配置。
- 不加入旧接口代理/re-export；上一轮显式备用模型和正常可选配置属于运行策略，不作为旧代码兼容删除。

## 评测流程

- 版本化数据集、独立 grader、实际 AskAgent + AgentHarness、每次试验独立状态。
- 离线控制模式和真实模型模式严格分开，报告标记模式、Git 版本、数据集/评分器哈希、运行参数和重复次数。
- 成功率与 Wilson 区间、按任务统计 pass@k / pass^k、任务覆盖、工具选择/参数、引用、策略遵守、恢复、超时/取消、延迟分位数、模型/工具调用量。
- token 使用区分供应商数据与 TokenBudget 估计；缺失供应商数据或价格时不生成费用数字。
- JSON 原始明细、Markdown 结论、HTML 图表；支持基线比较和 CI 回归门禁。
- 故意漏调工具、返回错误事实或去掉恢复的对照运行必须被评分器检出，避免漂亮但无效的分数。

## 执行与验收

至少三轮重复控制评测，另跑退化对照；输出真实模型未执行时的明确原因。每项需求执行后端测试、类型/构建检查；影响聊天运行时后回归前端联调。评测框架也测试统计公式、隔离、评分失败、比较不兼容、门禁、脱敏及报告生成。
