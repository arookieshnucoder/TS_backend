## 评分器验证与故障定位

- 漏调工具：28% 通过，18 题退化；工具 recall、成功工具证据和引用均降为 0。完全没有调用时 precision 为 N/A，没有把空调用当成 100% 正确。
- 错误回答：24% 通过，19 题退化；工具与证据维度仍通过，但回答事实和引用为 0，说明执行链正常不能代替答案正确性。
- 关闭恢复：88% 通过，模型临时故障、幂等工具重试、明确备用模型三题各失败 3 次；标准配置同三题均成功。这是受控故障下恢复策略的收益，不能外推为所有真实任务提升 12 个百分点。
- 三组对照均触发通过率及基线回归门禁；前两组另触发关键边界门禁。专项测试证明仅一个关键案例失败、总通过率仍有 96% 时，也会直接拒绝。
- MCP 是真实 SDK/stdio 连接和调用；工作区工具、记忆工具、批次原子验证、非幂等副作用次数、取消、超时经过重复检查。

验证：后端 98 项测试通过、TypeScript 构建通过；前端 5 项联调测试通过。Chrome 1440/390/320 px 检查报告案例筛选、MCP 轨迹切换和横向溢出；修正手机宽度的哈希与表格排版。
