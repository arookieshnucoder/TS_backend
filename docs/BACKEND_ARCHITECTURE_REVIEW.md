## 当前职责

- AskAgent：读取 runtime 的决策预算，构建完整工具回合，循环、观察、返回答案。没有 SDK/HTTP/存储/MCP 导入，没有工具验证实现。
- HarnessRuntime：协议与身份、允许的工具定义、模型次数、整批预检、工具总量、信号合并。不能通过替换 workflow 绕过这些机制。
- AgentHarness：组装上下文、工具选择、运行时、恢复模型和事件，运行指定 workflow。
- ToolRegistry：参数/权限异常映射、单工具执行、幂等重试、取消、超时、结果截断。
- ChatSessionService：会话互斥、请求时间预算、消息/标题保存、完整运行记录。
- 组合根：选择默认实现、注入自定义实现。模型/工具/压缩契约不依赖组合根。

## 保留的显式策略

没有发现旧 reply/chatModel/contextHarness 的执行回退；它们在组装时明确拒绝。没有 Elasticsearch 失败后改用本地搜索的路径，检索后端在配置时选择。没有自定义 workflow 失败后改跑 AskAgent 的路径。

有限重试与**明确配置**的备用模型是上一轮需求要求的运行策略，仍集中在 harness，默认没有备用模型；不会重放已经完成的工具。标题失败保留已有真实标题、MCP 不可用隔离该服务、记录写入失败不改变答案，都是具名的非关键操作策略，不调用旧实现或制造数据。

MCP 的 stdio/HTTP/SSE 是协议传输选择，mcpServers/type 是第三方配置格式，不属于本项目旧代码回退。常规可选配置默认值保留，不把所有 `??` 误判为兼容分支。

旧会话文件需要用户在离线流程显式迁移；应用不批量删除或自动修改数据。后续演进应为持久化 schema 建立明确版本和独立迁移命令，而不是再次在读取器加入宽松降级。

## 第二轮核心路径清理（2026-10-12）

| 发现 | 清理结果 |
| --- | --- |
| AppConfig 仍允许缺失 MCP/观测配置，容器重复补默认路径 | 两个配置块改为必要字段；默认值只由 loadConfig 生成，关闭观测使用 enabled=false |
| 容器和 AgentHarness 重复检查模型 turn；AgentHarness 和 RecoveringModel 重复检查备用链 | 输入契约在组装入口校验，执行器使用已解析配置；旧接口名的特殊提示删除，未知注入字段仍明确拒绝 |
| 每次运行重新从可选选项补四个默认值 | AgentHarness 构造时解析一次；复制备用链描述，组装后的调用不会受外部数组和名称修改影响 |
| 空工具文本被替换为 “No matching evidence found.” | 观察和工具消息都保留真实空文本，避免把“空输出”补造成“未找到证据”的业务判断 |
| 缺失模型请求 ID 时用消息 ID 代替 | requestId 保留实际模型请求值，messageId 单独记录；正常 HTTP 请求 ID 仍由会话服务设置 |

保留的检查有明确责任：组装入口负责依赖/选项是否合法，模型和 MCP 边界负责协议与 schema，harness 负责预算、授权、批次和取消，会话服务负责空回答、事务及持久化状态。没有删除这些约束以换取更短代码。

明确配置的备用模型、幂等重试、标题失败保留原题名、单个 MCP 故障隔离和观测失败不影响回答，均维持原有功能约定。第三方 MCP 的标准导入格式继续支持。RecoveringModel 是内部已配置模型链的执行器，不再承担组装校验。

验证：后端 101 项测试、TypeScript 构建、前端 5 项联调均通过；冻结的 25 个离线控制案例每题 3 次，共 75/75，通过率及案例维度相对原发布基线无回归。报告保留于 data/evaluations/cleanup-r3。新增回归覆盖空工具结果、请求/消息身份区分、备用模型链的校验和配置快照。
