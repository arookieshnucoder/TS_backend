# Harness 重试与回退

恢复发生在当前模型回合或单个工具调用中。不会重新启动整个工作流，也不会重复已经成功的工具调用。每个回答拥有自己的备用模型选择状态，不影响并发问题。

## 模型请求

默认最多重试 2 次，即主模型最多尝试 3 次。仅重试 HTTP 408/425/429/500/502/503/504、连接错误与单次请求超时。认证、权限、参数错误、无效模型协议与普通程序错误直接失败。重试使用有上限的指数退避，每次传入相同上下文副本。

主模型可恢复错误耗尽后，如果配置了备用模型，切换到备用模型完成**同一个回合**。已有 tool call ID 和工具结果保留；成功切换后，当前运行的后续模型回合继续使用备用模型。备用模型耗尽后报告失败。未配置备用模型时不自动选择其他供应商。

这套机制覆盖 Agent 的模型决策、harness 内上下文压缩以及共享记忆摘要。记忆工具通过本次运行的 TextCompressor 端口生成摘要，跟随当前恢复模型，并记录模型事件和用量；持久化历史仅包含角色与正文，不绑定模型身份。聊天标题在回答成功保存后使用独立的最多 5 秒预算更新；标题失败或超时保留原题名，不改变已保存回答。其他业务工具自行配置的模型调用仍由其执行策略控制。

## 工具调用

只有 `RegisteredTool.idempotent === true` 的工具才会自动重试，默认最多 1 次。`defineReadOnlyTool` 自动设置只读与幂等；直接实现 RegisteredTool 时应明确设置幂等性。

MCP 根据 `readOnlyHint` 或 `idempotentHint` 建立幂等标记；写工具仍需要 Hub 的“允许修改数据”授权。MCP 断线后的安全工具可以在重试时重新连接。服务返回 `isError: true` 是业务错误，作为失败的 tool 结果交给 Agent，不盲目重复执行。

参数校验先于执行；非幂等工具、权限失败和一般业务失败最多执行一次。工具所有尝试与退避共享原有 `AGENT_TOOL_TIMEOUT_MS` 预算，避免扩大工具时间上限。最终失败仍返回规范的工具错误，Agent 可以调整参数、使用其他工具或说明限制。

## 取消与超时

`AGENT_MODEL_ATTEMPT_TIMEOUT_MS` 默认 30000，每次模型请求单独计时。即使模型忽略 AbortSignal，也会释放调用者并忽略迟到结果。会话原有 `LLM_TIMEOUT_MS` 仍是总时间预算，包含工具、退避和其他会话处理。总预算耗尽或用户取消立即终止，不触发新尝试或备用模型。

## 配置

| 环境变量 | 默认 | 范围 |
| --- | --- | --- |
| AGENT_MODEL_RETRIES | 2 | 0–5 |
| AGENT_TOOL_RETRIES | 1 | 0–3 |
| AGENT_RETRY_BASE_DELAY_MS | 250 | 0–30000 |
| AGENT_RETRY_MAX_DELAY_MS | 3000 | 0–60000，且不少于基础延迟 |
| AGENT_MODEL_ATTEMPT_TIMEOUT_MS | 30000 | 1–600000 |

设置 `LLM_FALLBACK_MODEL` 启用备用模型。可选 `LLM_FALLBACK_BASE_URL` 默认同主模型；同地址可复用主模型凭据。**不同地址必须提供独立的 `LLM_FALLBACK_API_KEY`**，避免意外把主供应商密钥发送到另一地址。密钥只能由进程环境提供，不从 `.env` 读取。

代码注入使用 `createChatAgent(..., { recovery, fallbackModels: [{ name, model }] })`。测试覆盖真实 LangChain HTTP 503 → 重试 → 备用模型、保留工具结果、取消、超时、失败耗尽和非幂等工具执行次数。
